# Summary
Basically a home base for the whole JOERL-WORLD ecosystem. Here's how I'd picture it, based on the dark/neon aesthetic your other tools already share:

# Core: App Launcher Grid
A card/tile grid, one per app — JoErl Video Player, Music Player, FPS Overlay, Borderless, Dimmest, Clipboard, Screenshot, Autohibernation. Each tile shows the app's icon, name, and a one-click Launch button. Bonus: detect if it's already running (e.g. via process name) and show a "Running" badge or bring the existing window to front instead of relaunching.

# Quick access

Jump-to-folder buttons (open JOERL-WORLD, Release, dist in Explorer)
Recent builds/version panel — read each project's version_info.txt or README.md to show current version + last modified date, so you can see at a glance what's stale

# Live system strip
Since FPS Overlay and Dimmest already track FPS/RAM/battery, the dashboard could show a slim status bar pulling from a shared local file or named pipe those tools write to — so you get one glance at system state without opening the overlay.

# Nice-to-haves

# Global hotkey to summon/hide the dashboard window
"Start with Windows" + tray icon, matching your other tools' pattern
Category grouping (Media / Gaming Tools / Utilities) as the app count grows
A "+" tile to quickly register a new app (path + icon) as you build more.


# Under the hood
A simple JSON config (apps.json) listing each app's name, exe path, icon, and category — the dashboard just reads it and renders tiles, so adding a new app later is editing a file, not touching code.


# JoErl Dev Dashboard — Setup

This bundle has the actual app code, but not Flutter's auto-generated
`windows/` runner folder (that has to be generated by your own Flutter SDK).
Here's how to wire it up:

## 1. Create the project shell
On your laptop, in a terminal:
```
flutter create joerl_dashboard
```
This gives you `windows/`, `android/`, etc. We only need `windows/`, `lib/`,
`pubspec.yaml`, and `assets/`.

## 2. Drop in these files
Copy over (replacing the generated versions):
- `pubspec.yaml`
- `lib/` (entire folder)
- `assets/` (entire folder)

## 3. Add a tray icon
`main.dart` expects `assets/tray_icon.ico`. Drop a small `.ico` in
`assets/` — you can reuse one of your existing app icons (e.g. resize
`icon.ico` from JoErl FPS or Dimmest) or make a new one.

## 4. Install packages
```
flutter pub get
```

## 5. Edit apps.json paths
`assets/apps.json` has placeholder paths like:
```
C:\JOERL-WORLD\JoErl Video Player\windows\joerl_video_player.exe
```
Update `exePath` / `folderPath` for each app to match where they actually
live on your machine (mostly `dist\`, `publish\`, or `bin\` folders based
on what I saw in your screenshots — double check each one).

`processName` should exactly match what shows up in Task Manager / `tasklist`
for that app — that's what powers the "RUNNING" badge.

## 6. Run it
```
flutter run -d windows
```

## 7. Build a release exe
```
flutter build windows
```
Output lands in `build\windows\x64\runner\Release\`.

## Notes
- The dashboard reads `apps.json` from **next to its own exe** at runtime
  (not just the bundled asset), so once it's built you can add new apps by
  editing that file directly — no rebuild needed.
- Closing the window minimizes it to the tray, same pattern as your other
  tools. Right-click the tray icon → Exit to fully quit.
- The "RUNNING" badge polls `tasklist` every 4 seconds — cheap, no extra
  permissions needed.
